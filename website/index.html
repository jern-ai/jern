From issue to governed pull request

Four deliberate steps. No hosted runner required.

  1. 01

    Connect

    Select only the repositories Jern Cloud may inspect through the GitHub App.

  2. 02

    Review

    Cloud opens a setup pull request with a pinned Action and least-authority baseline. It never merges it.

  3. 03

    Run

    A maintainer dispatches an issue or task. GitHub Actions executes Jern with your provider secret under the protected policy.

  4. 04

    Review

    Successful changes arrive on an isolated branch as a pull request, linked to encrypted run evidence and normal repository controls.

The boundary is the product

Keep execution close. Centralize control.

Jern Cloud is a control plane around the open-source Jern runtime. Enforcement happens where the code runs. Cloud authorizes the run, reserves its cap, and retains its evidence without receiving your model credential.
